# Automation Studio 2.0 — аудит і результати

Дата: 22.11.2026. База: наявний GitHub-проєкт Automation Studio, без переписування з нуля.
Документ описує перевірену версію 2.0. Актуальний стан публікації дивіться в GitHub Actions.

## Пріоритети аудиту

| Пріоритет | Проблема | Виправлення |
|---|---|---|
| Високий | Розмите пояснення послуг | Єдиний розділ про заявки, CRM, розрахунки й контроль, CTA до контактів |
| Високий | Немає відеофайла, декоративний Play | Справжня конфігурація MP4/YouTube; до появи URL — робочі альтернативи без Play |
| Високий | Дрібний і недостатньо контрастний текст | Виправлено кольори світлих панелей, підписи ілюстрації CRM та контрольні елементи |
| Середній | Галерея без окремого zoom, фокус скидався між зображеннями | Zoom/fit, прокрутка збільшеного кадру, стабільний фокус і повернення до кнопки |
| Середній | Не всі ARIA controls посилалися на наявні панелі | Чотири постійні tabpanel, неактивні приховані, ArrowUp/Down для мобільної схеми |
| Середній | Надмірний масштаб окремих заголовків/відступів | Контекстні clamp(), компактні секції, вертикальна мобільна схема |
| Середній | Неповна персоналізація і Twitter metadata | Ініціали ОН, чесний досвід, «Мій підхід», метадані кожної сторінки, noindex для 404 |
| Середній | Немає повторюваних lint/browser перевірок | ESLint, check-build, browser-smoke, перевірки у workflow |

## Контент і довіра

Головний заголовок, логотип, кольори, дві основні кнопки, схема головної, інтерактивний
LeadFlow, карточка проєкту та справжня галерея збережені. Додано конкретний підзаголовок,
пояснення адаптації під бізнес і CTA «Обговорити мою задачу». Контакти власника не змінені.
Російський інтерфейс знімків чесно пояснений українською. Випадкові фотографії, відгуки,
клієнти, стаж, доходи та обіцянки гарантованої економії не додавалися.

Метрики звірено із збереженими матеріалами навчальної CRM від 21.11.2026:
протоколом перевірки, знімками замовлень і сповіщень та звітом стрес-тесту.
Збережені 25 заявок, 25 звірених розрахунків, 3 навмисні дублікати та 25 отриманих листів
підтверджені історичними матеріалами. Лише локальний `stress-local-checks.json` не вважався
доказом реальної відправки. Підтвердження прав менеджера також є в окремому протоколі.
Сирі CRM-матеріали, внутрішні ID, службові акаунти й приватні посилання до репозиторію не копіювалися.

Нова одночасна серія 25 форм після виправлення блокування не проводилася — це пояснення
збережене. У цій роботі нові заявки й листи не надсилалися, CRM не змінювалася.
Усі п’ять опублікованих PNG візуально перевірені: приватних URL/акаунтів/контактів не видно;
імена в навчальному прототипі — тестові дані.

## Технічні зміни

- Динамічний модуль Motion features та LazyMotion замість повного motion-компонента.
- Основний JS chunk: приблизно 392 → 314 kB без gzip; новий відкладений модуль — 37 kB.
  Сумарний JS приблизно 351 kB; основний chunk gzip — близько 99 kB. Це розмір файлів,
  а не оцінка швидкості чи Lighthouse. Попередній розмір узято з логів попередньої збірки.
- Локально збираються лише потрібні latin/cyrillic файли шрифту, font-display: swap.
  Це скорочення набору ресурсів, без твердження, що раніше всі шрифти завантажувалися браузером.
- Tailwind сканує src явно, сторонні файли документації не розширюють CSS.
- PNG збережені, lazy loading та async decoding; розміри областей галереї стабільні.
- YouTube не завантажується до натискання; невалідний URL показує альтернативи.
- Статичні маршрути, canonical, OG, Twitter Cards, sitemap, robots, favicon з урахуванням base path.
- Заголовками кешування керує GitHub Pages. У застосунку їх довільно налаштувати не можна;
  JS/CSS/шрифти мають hash в імені.

## Виконані перевірки

- TypeScript (`pnpm check`), ESLint (`pnpm lint`), production build, `pnpm check:build` — пройдені.
- Автоматизований браузерний `runBrowserSmoke` запущено через підтримуваний REPL Codex:
  головна і LeadFlow × 320/375/390/768/1024/1440/1920 px — 14 комбінацій.
  Один H1, без горизонтального переповнення й обтинання H1–H3; усі aria-controls мають ціль.
- Перевірені меню/Escape, ArrowDown/End у схемі, галерея/zoom/перемикання/Escape,
  повернення фокуса, CTA до контактів, email і Telegram. Повідомлення не надсилалися.
- Пряме відкриття й перезавантаження кейса працюють. Ресурси й посилання локальної збірки
  перевірені на існування. У перевірених браузерних сесіях console errors/warnings не було.
- Контраст статичного тексту на однотонних панелях перевірено розрахунком відносної яскравості
  за computed styles; виявлені порушення виправлено. Це обмежена перевірка, не повний WCAG-аудит:
  градієнти, складне альфа-компонування та весь screen-reader сценарій автоматично не оцінювалися.
- Підтримка prefers-reduced-motion у CSS та MotionConfig збережена і перевірена в коді.
  Примусова емуляція системної настройки не проводилася.

Протоколи браузера та контрольні PNG збережені у локальній папці qa батьківського проєкту.
Файл `scripts/browser-smoke.mjs` входить до підготовленої версії для повторного запуску.

## Межі перевірки й наступні кроки

- Lighthouse у доступному середовищі не встановлений; відповідного засобу браузерного аудиту
  немає. Оцінки Performance/Accessibility/Best Practices/SEO не виміряні, 90+/95+ і 100/100
  не заявляються. Потрібен окремий Lighthouse-запуск після публікації.
- Немає справжнього відео, фото та синхронізованих субтитрів. Компонент і сценарій готові,
  фактичне відтворення власного MP4/YouTube ще слід перевірити після додавання ролика.
  Жодне тестове чи стороннє відео не видається за демонстрацію LeadFlow.
- Перевірено один доступний браузер; Safari/Firefox і фізичні телефони не тестувалися.
- Публікацію версії 2.0 власник окремо погодив після перевірки результату.
  Після її окремого запуску треба дочекатися GitHub Actions Success і перевірити публічні URL.

Фінальне уточнення перевірки: на 320 px знайдено й прибрано горизонтальне переповнення,
спричинене `body min-width: 320px` разом із системною смугою прокрутки. Тест тепер
порівнює scrollWidth з clientWidth, а не innerWidth. Повторний прогін усіх 14 комбінацій
пройшов, включно з доступною шириною 305 px при viewport 320 px. Після останніх
виправлень контрасту перевірені desktop home і mobile case; нових порушень для
однотонного статичного тексту за використаним методом не виявлено.
Портативні протоколи входять у `reports/browser-smoke.json` та `reports/browser-final.json`.
